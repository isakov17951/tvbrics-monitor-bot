# TV BRICS — новости иранских партнёров

Бот собирает новости в разделе Ирана на tvbrics.com на RU, EN, CN, PT, ES и AR.
В подборку попадают статьи со ссылкой в тексте на одного из 12 партнёров,
перечисленных в `config.py`. Отправляет полные заголовки и ссылки в Telegram.

По умолчанию период — 10 календарных дней: сегодня и 9 предыдущих дней,
по московскому времени. Будущие даты исключаются. Период задаёт `DAYS_BACK`.

## Что исправлено после обновления сайта

- Сбор читает действующий фильтр `.js_filter_country`, карточки `.news-card`
  и параметры `.js_news_list_show_more` нового сайта.
- Адрес запроса, ID Ирана и параметры следующей страницы берутся из HTML
  нужной языковой версии. Номера языковых лент не зашиты в коде.
- Сохранён исходный способ работы через Playwright и Chromium. После выбора
  Ирана и нажатия «Показать ещё» бот ждёт соответствующий ответ сайта и
  подтверждение обновления интерфейса, вместо фиксированного ожидания.
- Полный заголовок берётся из статьи, а не из сокращённой карточки.
- Ссылки партнёров проверяются в тексте статьи, отдельно от рекламы и меню.
- Даты распознаются в том числе на китайском; первый день периода учитывается
  целиком. Старая карточка среди свежих не останавливает обход.
- Ошибки сайта и отдельных статей отображаются как неполный поиск. В Actions
  такой запуск получает статус ошибки, даже если удалось собрать часть подборки.
- При HTTP 401/403/429 или странице проверки браузера сбор останавливается.
  Бот сообщает о проблеме доступа и не пытается обходить проверку сайта.
- Найденная новость отмечается обработанной после подтверждения доставки всем
  настроенным получателям. Подтверждения сохраняются отдельно для каждого чата;
  при повторном запуске доставленные сообщения не отправляются ещё раз.
  Если Telegram принял сообщение, но соединение оборвалось до подтверждения,
  повторная отправка всё же возможна.
- Исходная таблица `seen` и Excel-экспорт совместимы. Старый архив сохранён.

## Обновление действующего бота

Пошаговая инструкция — в `UPDATE_RU.md`.

## Локальная установка и запуск

Нужен Python 3.10 или новее; проверено на Python 3.12.

```sh
python -m pip install -r requirements.txt
python -m playwright install chromium
```

Скопируй `.env.example` в `.env`, заполни `BOT_TOKEN`. Для плановой отправки
нужен также `CHAT_ID` (один ID или несколько через запятую). Для интерактивного
бота без расписания достаточно токена.

```sh
python bot.py
```

В Telegram: `/start` → «🔍 Запустить поиск». Компьютер и процесс должны работать.
Не запускай несколько копий `bot.py` с одним токеном одновременно.

## Проверка без Telegram

Токен для этой команды не нужен. Команда не меняет SQLite и не отправляет сообщения:

```sh
python search_once.py --dry-run
```

Проверка одного языка, другого периода и всех статей, включая уже известные:

```sh
python search_once.py --dry-run --langs RU CN --days 10 --include-seen --json check.json
```

`--include-seen` разрешён только вместе с `--dry-run`.
В JSON содержатся результаты, ошибки и список полностью проверенных языков.
Код завершения `0` означает полный проход, `1` — ошибки сбора или доставки.

Автоматические проверки (без запросов к сайтам и Telegram):

```sh
python -m unittest discover -s tests -v
```

Фикстуры в `tests/fixtures` основаны на действующей разметке шести версий сайта;
тексты статей и заголовки в них заменены учебными примерами.

## Результаты проверки исправления

Проверены сохранённые ответы всех шести языковых лент, распознавание дат,
фильтрация партнёров и сценарии сбоев. 23 автоматические проверки проходят.
На действующем сайте проверены выбор Ирана и подгрузка следующей страницы
в браузере. При диагностике прочитаны реальные статьи с партнёрскими ссылками,
но дальнейшие HTTP-запросы получили страницу DDoS-Guard.

Полный проход итогового кода в Chromium и отправка через твой Telegram-токен
в этой среде не подтверждены. Нужен контрольный запуск в твоём GitHub Actions
или на сервере по `UPDATE_RU.md`. Если там появится сообщение о проверке
доступа, потребуется разрешить автоматический сбор у администрации TV BRICS.

## GitHub Actions

`.github/workflows/search.yml` запускается ежедневно в 09:00 по Москве,
а также вручную через **Actions → Поиск новостей иранских партнёров → Run workflow**.
Секреты репозитория: `BOT_TOKEN` и `CHAT_ID`.

После поиска workflow сохраняет `seen_news.db` обратно в репозиторий,
в том числе после частичного сбоя. Это сохраняет успешные доставки и позволяет
повторить недоставленное. Нужны права GitHub Actions на запись содержимого.
Один и тот же workflow не выполняется параллельно сам с собой.
Если во время поиска кто-то изменит ветку, шаг `git push` может потребовать
ручного разрешения конфликта; ошибка сохранения будет видна в Actions.

Не запускай одновременно плановый поиск и локального бота с разными копиями
одной базы, если важно общее исключение повторов: локальная база сама с GitHub
не синхронизируется.

Excel: **Actions → Экспорт в Excel → Run workflow**. Ранее накопленные данные
сохраняются. Поиск не требует настройки OpenAI или какого-либо AI API.

## Файлы

| Файл | Назначение |
|---|---|
| `scraper.py` | Запросы сайта, фильтры, даты, разбор статей |
| `config.py` | Партнёры, языки, период, тайм-ауты |
| `bot.py` | Интерактивный Telegram-бот |
| `search_once.py` | Actions и проверка без отправки |
| `delivery.py` | Формат и подтверждённая доставка сообщений |
| `db.py` | Архив и подтверждения по получателям |
| `export_excel.py` | Прежний Excel-экспорт |
| `tests/` | Проверки критичных сценариев |

База по умолчанию находится рядом с кодом. Другой путь можно задать переменной
окружения `DB_PATH`. Не удаляй действующую базу при обновлении.
